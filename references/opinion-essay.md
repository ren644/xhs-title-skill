# 观点与随笔标题引擎

用于观点随笔、个人表达、社会观察、情绪思考和叙事性口播。目标不是把文章压成一句正确摘要，而是找到最值得传播的矛盾。

## 先重建文章

在内部回答：

1. 什么事件或感受触发了作者？
2. 大多数人通常怎样理解这件事？
3. 作者真正不同意的是什么？
4. 这个矛盾给具体的人带来了什么代价？
5. 作者最有辨识度的原句是哪一句？
6. 文章最后留下了什么没有解决的问题或余味？

不要只提炼中心思想。观点文章通常同时包含判断、证据、个人处境和情绪余波，至少从其中 3 层生成标题。

## 判断这篇是否承担 IP 任务

如果用户目标是个人 IP，再内部回答：

- 这个判断只是这篇文章的结论，还是作者会长期坚持的命题？
- 读者会记住一个观点，还是记住“这个作者总能怎样看问题”？
- 标题是否仍给读者具体利益，而不是只表达作者自己？

IP 候选优先保留“具体对象 + 稳定判断”。若一个更锋利的判断只是从正文推导出来、正文没有明确论证，标注 `需正文补强`，不要把推断当成原意。

## 六种传播单元

### 1. 结论直击

直接给出反直觉或高密度判断，同时保留具体对象。

- `真正让人累的，不是工作多`
- `效率提高后，我反而更忙了`

### 2. 矛盾前置

把文章最不公平、最荒诞或最难解释的反差放进标题。

- `越想把生活过好，越没有生活`
- `人人都能表达后，真话更少了`

### 3. 代价落地

把抽象变化翻译成一个人失去了什么、开始害怕什么或不得不做什么。

- 不只写“职业危机”，要写“开始不敢投稿”。
- 不只写“关系内耗”，要写“每句话都要先猜对方”。

### 4. 原句截取

优先保留作者独有的比喻、短句、反问或带刺表达。允许轻微压缩，但不要把它改成常见营销句式。

原句过于文学或主题不明时，在前半句补充主题锚点；不要只留下读者看不懂的漂亮句子。

### 5. 读者照镜子

让目标读者认出自己正在经历的状态，而不是笼统写“所有人”。

- `写得越认真，越不敢发出去`
- `会表达的人，也开始害怕表达`

### 6. 未闭合问题

让读者知道问题是什么，但把关键判断留在正文。

- `当努力不再稀缺，我们还剩什么`
- `如果技巧都能复制，经验还值钱吗`

问题必须由正文回答或充分讨论，不能只用问号假装深刻。

### 7. 作者命题

把一次性判断提升为可持续的作者视角，但不能超出正文：

- `AI会生成标题，我更在意它怎么判断`
- `工具可以替我写，判断力不能一起外包`

第一种更贴近具体行动，通常可直接使用；第二种立场更强，只有正文明确讨论“判断不能外包”时才可直接使用，否则标注 `需正文补强`。

## 网感改写

把“关于 X 的思考”“X 时代的困境”“浅谈 X”改成具体的人话：

- 抽象现象 → 谁正在失去什么
- 宏大判断 → 一个具体反差
- 中性总结 → 作者真实态度
- 漂亮句子 → 主题锚点 + 漂亮句子

避免高频 AI 腔：

- “在这个时代”开头的空泛感叹
- “真正的 X 从来不是 Y”连续套用
- “写给所有 X 的一封信”
- “我们终将……”式无证据升华
- 只替换名词就能用于任何文章的金句

## 默认候选配比

生成草案时优先覆盖：

- 3 个第一眼看懂的直给标题
- 3 个对比冲突或痛点共鸣标题
- 2 个原句截取标题
- 2 个情绪价值、读者代入或未闭合问题

IP 模式额外生成 2 个作者命题候选，并用读者利益和正文证据淘汰空洞自我表达。

这只是保证差异的起点，不是必须展示的分组。最终只保留真正成立的标题。
