# 点击、涨粉与个人 IP

标题可能同时影响点击、关注和作者认知，但一次只能有一个主任务。先判断内容在账号中的作用，再决定排序标准。

## 三个目标不是一回事

### 点击

回答：`我为什么现在要点开？`

依赖：

- 第一眼看懂主题
- 与当前处境直接相关
- 有具体回报、冲突或适度信息缺口
- 封面、标题与正文承诺一致

点击面很广但吸引错人，属于无效流量。

### 涨粉

回答：`我为什么以后还值得看这个作者？`

依赖：

- 进入的人与账号长期方向一致
- 作者展示了可重复的方法、经验或判断能力
- 正文兑现承诺并建立信任
- 读者能预期后续还有同类价值

“有用”能促成一次关注，但不一定让人记住作者。

### 个人 IP

回答：`以后再看到这个作者，我会因为什么认出他？`

IP 标题至少传递一种稳定信号：

- `长期议题`：作者持续关注什么问题。
- `独特能力`：作者反复把什么变成什么，例如把经验变成工具、把复杂问题变成清楚流程。
- `稳定判断`：作者对一个问题长期坚持什么看法。
- `表达辨识度`：标题保留作者原话、比喻或语气，而不是万能模板。

IP 标题仍要给读者利益。只有“我做了什么”的自我介绍不能因为带第一人称就获得高分。

## 判断内容在账号中的任务

| 内容任务 | 主要目标 | 标题优先表达 | 常见风险 |
| --- | --- | --- | --- |
| 入口帖 | 精准点击 | 目标人群、痛点、答案缺口 | 受众过宽 |
| 信任帖 | 涨粉 | 过程、证据、复盘、判断 | 像流水账 |
| IP 锚点帖 | 作者认知 | 作者命题、方法或稳定视角 | 只顾表达自己 |
| 资源帖 | 交付与触达 | 工具、清单、使用场景 | 拿走即走 |

一篇资源帖可以兼任 IP 锚点帖，但标题必须让读者看到作者的方法或判断，不能只写“开源、免费、GitHub、直接拿”。

## IP 模式的最小作者命题

在内部完成其中一句：

- `我长期关注___。`
- `我擅长把___变成___。`
- `我相信___，而不是___。`

只使用正文能够支持的一句。账号信息不足且不同答案会改变标题方向时，问：

`你希望读者记住你会做什么，还是你相信什么？`

如果用户不回答，优先从正文真实动作中提炼能力，不擅自发明人设。

## 四个候选池

### 点击优先

- 具体痛点 + 解决方向
- 明确对象 + 一个未闭合答案
- 真实数字 + 结构性回报
- 可解释的对比或反转

### 涨粉优先

- 目标读者 + 可复用方法
- 真实经历 + 复盘能力
- 具体问题 + 稳定解决框架

### IP 优先

- 具体主题 + 作者判断
- 作者真实动作 + 可重复能力
- 常见看法 + 作者能够论证的不同命题
- 当前案例 + 长期内容主线

### 平衡首选

保留一个主题锚点、一个点击理由和一个长期价值信号。不要同时塞入人群、数字、痛点、结果、方法、IP 和搜索词。

## 拿走即走风险

以下标题可以有点击，但通常不适合作为涨粉或 IP 首选：

- 只强调免费、开源、领取、链接或 GitHub
- 只罗列支持的平台或工具名称
- 只说“我做了一个东西”，没有读者问题或作者方法
- 只靠热点名称，离开热点后看不出账号方向

修复方式不是删除资源信息，而是把资源放到副标题、正文开头或候选组中；主标题优先表达它解决什么问题、为何这样设计或体现什么判断。

## 语义聚类

为草案写出内部摘要：

`这个标题邀请[哪类读者]，因为[什么点击理由]，并让他记住作者[什么价值]。`

摘要相同的标题归为一组。每组最多保留 2 个，且必须只改变一个主要变量。换词、换标点和换语序不算新方向。

## 模式化排序

所有标题先通过真实性、清晰度、目标相关性和兑现度硬门，再按模式排序：

| 模式 | 最高权重 | 次高权重 | 降级项 |
| --- | --- | --- | --- |
| 点击 | 相关性、信息缺口 | 具体性、一眼理解 | 讲完答案或主题模糊 |
| 涨粉 | 账号主线、持续价值 | 信任、方法感 | 一次性猎奇 |
| IP | 作者命题、辨识度 | 读者利益、记忆点 | 自我介绍、套话、资源诱导 |
| 搜索 | 意图匹配、主关键词 | 自然度、内容覆盖 | 关键词堆叠 |

## 数据迭代

拿到真实数据后，把曝光后的点击表现、阅读后的关注变化和互动反馈分开观察。一次只调整一个变量，例如：

- 主题是否前置
- 缺口偏大还是偏小
- 作者命题强还是弱
- 封面和标题各自承担什么

单篇样本不足以宣布通用规律。记录“什么内容任务 + 什么受众 + 什么标题变量”后再跨笔记比较。
