# 教程、测评与产品标题参考

主要用于教程、清单、工具测评、产品体验和攻略内容。先从 `viral-hooks.md` 选择一个主钩子；观点随笔、个人表达或社会观察改读 `opinion-essay.md`。先保证标题真实可兑现，再使用公式。

## 角度选择表

| 角度 | 适合内容 | 结构提示 | 主要风险 |
| --- | --- | --- | --- |
| 人群定位 | 受众差异直接影响答案 | `[具体人群] + [问题/结果]` | 贴标签、受众过窄 |
| 具体场景 | 方法只在某个时机有用 | `[场景/阶段] + [行动或避坑]` | 场景与正文无关 |
| 明确价值 | 正文有清单、步骤或实测 | `[真实数量/经验] + [能得到什么]` | 编造数字或收益 |
| 痛点避坑 | 正文能解释错误及后果 | `[常见动作] + [具体代价/错误]` | 恐吓、夸大损失 |
| 反常识观点 | 正文有完整论证 | `[常见看法] + [相反判断]` | 为反对而反对 |
| 对比 | 正文有两套方案或前后变化 | `[A] vs [B] + [关键差异]` | 偷换条件、假对比 |
| 信息缺口 | 正文确有关键原因或发现 | `[异常/结果] + [关键问题]` | 故意说半句、答非所问 |
| 热点关联 | 热点已确认且内容有独立价值 | `[热点对象] + [本领域切口]` | 过时、硬蹭、事实错误 |
| 方法/IP | 当前案例能体现作者长期能力 | `[具体问题] + [作者方法或判断]` | 只顾自我介绍 |

## 1. 人群定位

把对答案真正有影响的人群特征放进标题，如新手、租房者、通勤时间、预算区间或使用阶段。

可用结构：

- `新手第一次做 X，先看这 Y 点`
- `[具体条件]的人，X 要这样选`

只用与内容结论有关的特征。不要为了精准而制造冒犯性标签。

## 2. 具体场景

把宽主题收窄到读者正在经历的时机或动作。

可用结构：

- `准备 X 前，先确认这 Y 件事`
- `每天 X 分钟，我会这样做 Y`

“上班前”“搬家后”“第一次购买”等场景应在正文中真正出现。

## 3. 明确价值

适合清单、教程、复盘、测评和经验总结。具体不等于夸张；数字只能来自正文。

可用结构：

- `我实际用过的 Y 个 X`
- `做完 X，我留下这 Y 条经验`
- `X 怎么选：先看这 Y 个区别`

不要把“几个”强行换成虚构数字，也不要把主观体验写成普遍结果。

## 4. 痛点或避坑

指出读者正在付出的真实成本，并在正文给出原因和替代方案。

可用结构：

- `X 总是失败，可能卡在这一步`
- `别急着 X，先排除这 Y 个问题`

避免“再不看就亏惨”“所有人都做错了”等无法证明的恐吓句式。

## 5. 反常识观点

把有证据的分歧写清楚，适合观点文或复盘，不适合证据薄弱的内容。

可用结构：

- `X 不一定更好，关键是 Y`
- `我不建议新手先做 X`

标题的反转必须在正文中完成论证，并交代适用条件。

## 6. 对比

让读者看到选择差异，而不是只写“前后对比太惊人”。

可用结构：

- `X 和 Y 怎么选？差别在这`
- `同样做 X，这两种方法结果不同`

对比双方需处在可比较条件下；没有实测结果时写“区别”或“选择”，不要写“完胜”。

## 7. 信息缺口

先给足主题，再保留一个值得点开的关键答案。

可用结构：

- `我停用 X 后，才发现问题在 Y`
- `X 看着一样，真正差在这里`

避免代词堆叠，例如“这个东西竟然这样”；标题应让新读者知道讨论对象。

## 8. 热点关联

只在热点仍相关、事实已核实、与正文有自然连接时使用。标题应提供独立信息，热点消失后仍有阅读价值。

可用结构：

- `[已确认事件]之后，普通人最该看懂的 X`
- `从[已确认作品/事件]看 X 的 Y 个细节`

没有联网能力或用户未提供可靠背景时，不主动声称某话题“正在热搜”“全网都在讨论”。

## 9. 方法与个人 IP

工具、教程和资源内容如果承担个人 IP 任务，不要只罗列功能或下载方式。优先回答：作者为何这样设计、展示了什么可重复能力、读者能学会什么判断。

可用结构：

- `[具体问题] + [作者如何把它变成方法]`
- `[工具能做什么] + [作者更在意的判断]`
- `[当前成果] + [下一篇可持续主线]`

“免费、开源、GitHub、直接拿”可以作为发布信息，但会吸引拿走即走的资源流量，不得自动排为 IP 首选。

## 封面与笔记标题协同

- 封面主标题负责冲突、情绪或记忆点，默认 6 至 12 个可见字符。
- 笔记标题补足对象、场景、关键词或具体回报。
- 两者承诺一致但不逐字重复。

例：

- 封面：`标题别只会生成`
- 标题：`我把起标题的判断方法做成了Skill`

## 常见弱题修复

| 弱点 | 修复方式 |
| --- | --- |
| “分享几个干货” | 说清对象、场景和实际内容；数字必须真实 |
| “一定要看” | 改成读者看完能解决的具体问题 |
| “太绝了” | 补充绝在哪里，或删除空情绪词 |
| 同时承诺多个结果 | 只保留正文最能兑现的一个 |
| 标题只有悬念没有主题 | 先写主题，再保留一个信息缺口 |
| 搜索词连续堆叠 | 选一个主关键词，其余用自然语言表达 |
| 所有候选只是近义改写 | 分别改用人群、场景、价值或观点角度 |

## 组合原则

一个标题通常组合两个角度已经足够，例如“人群 + 场景”“场景 + 避坑”“关键词 + 明确价值”。不要把人群、数字、冲突、热点、emoji 和悬念全部塞入同一标题。
